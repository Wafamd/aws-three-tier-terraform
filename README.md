# AWS Three-Tier Web Application (Terraform)

A complete, deployable three-tier stack: public ALB → private Auto Scaling EC2 → private RDS,
with an S3 bucket for assets.

```
                    Internet
                        │
        ┌───────────────▼───────────────┐   public subnets  (10.0.0.0/24, 10.0.1.0/24)
        │   Application Load Balancer   │   + NAT Gateway
        └───────────────┬───────────────┘
                        │  SG: only ALB may reach app
        ┌───────────────▼───────────────┐   private app subnets (10.0.10.0/24, 10.0.11.0/24)
        │  Auto Scaling Group (EC2)     │   no public IPs, SSM access only
        └───────────────┬───────────────┘
                        │  SG: only app may reach DB
        ┌───────────────▼───────────────┐   private data subnets (10.0.20.0/24, 10.0.21.0/24)
        │   RDS MySQL (optional Multi-AZ)│  no route to the internet at all
        └────────────────────────────────┘

        S3 (assets) ← reached via a VPC gateway endpoint, not the NAT
```

## Files

| File | Contains |
|---|---|
| `versions.tf` | Provider pinning, optional S3 remote backend |
| `variables.tf` | Every knob, with defaults that fit a sandbox |
| `vpc.tf` | VPC, 3×2 subnets, IGW, NAT, route tables, S3 endpoint |
| `security_groups.tf` | The three chained SGs that enforce tier isolation |
| `alb.tf` | Load balancer, target group, HTTP/HTTPS listeners |
| `compute.tf` | IAM role, launch template, ASG, CPU target tracking |
| `rds.tf` | Subnet group, generated password, DB instance |
| `s3.tf` | Encrypted, versioned, private bucket |
| `templates/user_data.sh` | nginx bootstrap serving `/` and `/health` |

## Deploy

```bash
aws sts get-caller-identity          # confirm the right account
cp terraform.tfvars.example terraform.tfvars
# edit terraform.tfvars — at minimum, narrow ingress_cidrs to your IP

terraform init
terraform plan
terraform apply

terraform output app_url
```

The ALB needs 2–4 minutes after apply before targets pass health checks. If the URL
returns 503, watch the target group in the console or run:

```bash
TG=$(aws elbv2 describe-target-groups --names threetier-dev-tg \
  --query 'TargetGroups[0].TargetGroupArn' --output text)
aws elbv2 describe-target-health --target-group-arn "$TG"
```

### Getting onto an instance

There is no SSH key and no bastion — instances are reachable through Session Manager:

```bash
aws ssm start-session --target <instance-id>
```

### Reading the DB password

```bash
aws secretsmanager get-secret-value \
  --secret-id $(terraform output -raw db_secret_arn) \
  --query SecretString --output text | jq
```

## Tear down

```bash
terraform destroy
```

Set `deletion_protection = false` first if you enabled it, or both the ALB and RDS
will refuse to be deleted.

## Cost

Defaults are close to the cheapest working version of this, but it is **not** free tier.
The NAT Gateway is the surprise on most people's first bill — roughly $32/month plus data
processing, running whether or not you use it. Ballpark for the defaults in `ap-south-1`:

| Item | Approx/month |
|---|---|
| NAT Gateway ×1 | ~$32 |
| ALB | ~$18 + LCU |
| 2× t3.micro | ~$15 |
| db.t3.micro + 20 GB gp3 | ~$15 |
| S3, secrets, data transfer | ~$1–3 |

`terraform destroy` when you're done experimenting.

## What's deliberately left out

Things worth adding next, roughly in order of value:

1. **Remote state** — uncomment the S3 backend block in `versions.tf` and create the
   bucket + lock table first. Local state breaks as soon as a second person touches this.
2. **HTTPS** — request an ACM cert, set `certificate_arn`, add a Route 53 alias record
   pointing at `alb_dns_name` / `alb_zone_id`.
3. **Real application deployment** — `user_data.sh` bakes nginx at boot, which is slow
   and unversioned. Build an AMI with Packer or pull an artifact from the S3 bucket.
4. **ALB access logs + VPC flow logs** — both off here to keep the bill down.
5. **CloudWatch alarms** — 5xx rate on the ALB, unhealthy host count, RDS CPU/storage.
6. **Modularization** — once this shape is familiar, split `vpc`/`compute`/`data` into
   modules and pass an env tfvars per workspace.

## Notes on the security posture

- App and data subnets have no public IPs; only the ALB is internet-facing.
- Security groups reference each other rather than CIDRs, so the tier boundaries hold
  even if subnet ranges change.
- Data subnets have no NAT route — the database cannot reach the internet outbound.
- IMDSv2 is required on instances, EBS and RDS storage are encrypted, and the S3 bucket
  denies non-TLS requests.
- The DB password is generated by Terraform and stored in Secrets Manager. It will still
  appear in state, which is the main argument for encrypted remote state.
